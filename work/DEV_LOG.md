- **runlog-timeouts** — Comprehensive run logging + the concurrency-freeze fix (branch `branch/runlog-timeouts`, commit `868becd`). **(1) Run log:** new `src/log.rs` — `RunLogger`: thread-safe (an `Arc` shared by every engine/worker; each call is a non-blocking send on an unbounded channel), non-blocking (a dedicated writer thread formats and writes each `[HH:MM:SS.mmm] [LEVEL] [CONTEXT] message` line to *both* `latest.log` (overwritten each run) and an archived `run-<YYYYmmdd-HHMMSS>.log`, flushing on every newline so a crash loses nothing), and degrades to a silent no-op when the files can't be created (logging never breaks a run). Log dir configurable via `--log-dir` / `CRUCIBLE_LOG_DIR` / config file (new `Config.log_dir`), default `~/.local/share/crucible/logs/`. Wired into: `main` (run start/end, both paths), setup (URL entered / model selected / config saved / launch summary in `App`), discovery (`GET {url}/models` request + `← 200 (N ms) — M models` / failure in the spawned task), the sequence executor (queue + every engine transition), all six engines (A per-iteration outcome; B per-step start/summary; C1/C2/C3 matrix/challenge/run start+complete; D sampling window), and — the richest source — `StreamWorker` itself: every worker (tagged `A:n`, `B{step}-{id}`, `C1:{size}k-d{depth}`, `C2:{id}`, `C3:free|constrained`) logs `→ POST {url} (stream=true, model=…, tokens_target=…)`, `← 200 OK (TTFB: …)`, non-200 bodies, `token #1 received (elapsed …)`, `token #N` every 50th, `stream complete: N tokens in Xs (Y t/s)`, and `failed: {full error}`. **(2) Freeze fix (user's "froze at level 16, step 5/7"):** three independent bounds, all logged — (a) **per-worker timeout**: `build_sweep` sets `WorkerPool::worker_timeout(cfg.timeout)`; each worker future is wrapped in `tokio::time::timeout` (new `StreamError::WorkerTimeout` variant) — on expiry the worker is dropped (socket closes), a synthesized terminal `Failed` event is relayed, the level records the partial tokens, marks the stream `timed_out`, and continues; (b) **stall detection**: the level drain loop is now a `tokio::select!` over the event channel and a 5 s watchdog — a live worker with no tokens for `DEFAULT_STALL_TIMEOUT` (30 s) gets a one-time `WARN … worker #N no tokens for 30s (last token at HH:MM:SS)` (distinguishes slow-server from hung-connection; the kill comes from (a)); (c) **step-level timeout**: each step's budget is `max(worker cap, 3× previous step wall)` (5-min floor when uncapped) — past budget → `WARN`; past 2× → `ERROR … STEP TIMEOUT — aborting level`, the supervisor task is aborted (its spawned worker tasks die with it), stranded workers are finalized as failed streams, the level is marked `aborted`/`degraded` (new `SweepLevel.timed_out_streams`/`.aborted` + `degraded()`, surfaced as a `· DEGRADED` flag in View 2's matrix), and the sweep proceeds to the next step. **Latent deadlock also fixed:** the pool's per-worker forwarder used to start only *after* `run()` completed — any stream longer than the 128-slot private channel deadlocked the whole level; the forwarder now runs concurrently (regression-tested with a 300-frame stream). **Verification:** `cargo build` ✓, `cargo test` **417/417 green** (23 new: logger file/overwrite/concurrency/degrade tests; pool long-stream, hang-kill, fast-worker; sweep step-budget/finalize/timeout-count/stall-once; integration hang-kill + step-abort + full step-lifecycle log-content tests), `clippy --all-targets` 0 warnings ✓, `fmt --check` clean ✓. **Live proof:** `crucible-llm --headless --engine concurrency --ladder 2,4 --timeout 5` against a real server that accepts and then hangs **completes in 15 s** (previously: froze forever) with the log showing `past the 5s budget`, `worker #N TIMEOUT after 5s — collected 0 tokens (killed)`, `…stalled — no data for 5s (killed)`, `[DEGRADED]` step summaries, and the sweep continuing to the next level; - **tui-interaction-audit** — Full audit + fix of the TUI interaction model (branch `branch/tui-guards`), driven by the user report that `[N] New Needle Test` "spams the server". **Findings:** (1) `n` fired *immediately with no confirmation* — `handle_key` → `KeyAction::NewNeedle` → `event.rs` called `app.start_niah()` directly; (2) `start_niah()` guarded only `niah.is_running()`, which is `false` for the whole sequence run except during Engine C1's own phase — so pressing `n` while Engines A/B/C2/C3/D ran spawned a **second, independent 77-request NIAH matrix hitting the endpoint concurrently** (the core bug); (3) one NIAH run = 7 sizes × 11 depths = **77 sequential streams** (up to 128k tokens each) with the count nowhere shown to the user; (4) `+` (concurrency step) and `c` (setup takeover, whose URL stage fires an HTTP discovery request) were unguarded mid-run; (5) `Space` "pause" only froze the *render clock* (`on_tick` early-return) — the engines kept firing requests; (6) the footer showed the same 5 hints in every state and there was no busy indicator. **Fixes:** (a) `n` is now a **modal confirmation** — the key path opens "Run NIAH test? 77 requests (7 sizes × 11 depths) — [Y]es / [N]o" (rendered in the footer); `y`/`Enter` confirms (spawning exactly one run), *any* other key cancels and is swallowed (a stray keypress can never both answer and trigger a second action); `Esc` cancels the prompt instead of quitting; `n` is **hard-locked while a `BenchmarkSequence` runs** (logged: "it runs as Engine C1 in the queue") and while a standalone NIAH run is active — `start_niah()` carries the same guards as defense in depth; (b) **`RunPause`** (new, `src/engines/sequence.rs`): a cooperative `AtomicBool` gate shared via `Arc` — `Space` toggles it and *every* engine run loop (A per iteration, B per ladder level, C1 per cell, C2 per challenge, C3 per run; standalone `n`-key NIAH too) calls `wait_while_paused()` **before spawning the next request unit**, so in-flight streams complete and resume continues exactly where it left off (counters untouched — no state corruption); the render loop/tick path never touch it (measurement-isolation invariant intact); `BenchmarkSequence::new` gained the gate parameter (8 args, `#[allow(clippy::too_many_arguments)]`); (c) `+` and `c` are locked mid-run with explanatory log lines (the sweep owns the ladder; no discovery request mid-benchmark); `e` (local file export) and view switching `1`-`5` remain live; (d) **state-aware footer** (`App::footer_line()`, pure + tested): Idle → `[1-5] Views | [R] Run Benchmark | [N] NIAH (77 req, confirms) | [C] Config | [E] Export | [Q] Quit`; Running → `[1-5] Views | [Space] Pause | [E] Export | [Q] Quit | [N] [C] [+] [R] locked` (dimmed); Paused → same with `[Space] Resume`; Confirming → the prompt itself; (e) **status bar** gains a `▸ BUSY` indicator while any benchmark load is in flight (sequence or standalone NIAH), alongside the existing `|| PAUSED`; (f) **View 3 legend** is state-aware: "Locked — NIAH runs as Engine C1 in the active benchmark sequence" / "Running NIAH matrix… 77 requests…" / accuracy + "confirms" / idle hint with the request count. **Files:** `src/engines/sequence.rs` (+`RunPause`, executor wiring, 2 new tests), `src/engines/speed.rs` / `concurrency.rs` / `capability/niah.rs` / `capability/reasoning.rs` / `capability/structured.rs` (pause builder + run-loop gate each), `src/engines/mod.rs` (re-export), `src/ui/app.rs` (guards, modal, Space gate, footer/status, 13 new tests), `src/ui/event.rs` (`NewNeedle` arm now inert — key path owns it), `src/ui/views/needle.rs` (legend), `tests/niah_test.rs` (legend assertion updated). **QA:** `cargo build` ✓, `cargo test` **394/394** (was 377;
