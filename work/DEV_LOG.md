- **freeze-metrics** — Fixed the "metrics keep changing after the run finishes" report (on `branch/freeze-metrics`). **Root cause:** the `MetricsState` `ArcSwap` snapshot was being re-published *after* the sequence completed — the forever-running 100 ms **hardware poller** (`main.rs` spawns it `if cfg.hardware`) calls `MetricsState::update()` on every tick, and each `update()` (a) re-stamps the writer-side `RollingSeries` with a fresh `aggregate_tps` sample (`0.0` once no streams are active → the hero graph keeps scrolling in zero samples, dragging the window average down) and (b) re-folds the `OverallAccumulator` (`elapsed_sec`/`duration_sec` grow on every call, `active_avg` drifts toward 0) → the **OVERALL METRICS** panel numbers shifted indefinitely after `AllComplete`. **Fix:** a **one-way `frozen` latch** on `MetricsState` (`freeze()`/`is_frozen()`, an `AtomicBool`); the `BenchmarkSequence` executor calls `self.metrics.freeze()` the instant it publishes `SeqPhase::AllComplete`, after which `update()` is a no-op — the rolling window, the overall accumulator, and the published snapshot all hold their final values, so *every* writer (engines, the hardware poller, anything else) stops mutating the data and the UI shows static numbers. **UI:** the Live hero now reads `final {window-avg} t/s │ peak {…}` (was `now/peak/avg`) with a `✓ COMPLETE (final, frozen)` title and a green border once frozen; the sequence header already shows `✓ ALL BENCHMARKS COMPLETE`.
