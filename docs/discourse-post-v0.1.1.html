Crucible LLM v0.1.1 — Big Update

The one where the numbers finally mean what you think they mean.

Since the initial release, we've been listening to feedback and pushing hard on the things that matter most. Here's what's new:

3 Visual Themes

Pick your vibe. Cyberpunk (cyan/purple/neon) is the default. Vampire (crimson/gold/gothic) for the dark aesthetic. Monochrome Pastel (soft/clean) for minimalists. First run asks you to pick — live preview as you arrow between them. Change anytime from Config.

Flat Out Engine

The number you want to quote. New "Flat Out" benchmark: 60 seconds at your server's optimal concurrency. Not 1 stream. Not max streams. The SWEET SPOT — where each user still gets great speed. This is your real-world maximum throughput. The number to compare servers by.

Accurate Token Counting

We were counting wrong. Now we're not. Turns out vLLM batches ~2.4 tokens per SSE frame. We were counting frames. That's a 3x undercount. Fixed. We now use the server's own token count (usage.completion_tokens) as the authoritative source. Our numbers match the server's numbers.

Works With Everything

Not just vLLM. Confirmed working with: vLLM, llama.cpp, LM Studio, Unsloth Desktop, SGLang, Ollama, TGI. Any OpenAI-compatible endpoint. If it speaks /v1/chat/completions, we benchmark it.

30 T/S Sweet Spot

The number that actually matters. Concurrency sweep now identifies your "Practical Sweet Spot" — the most users where each still gets ≥30 tokens/sec. Not the max-throughput knee (misleading). The real deployment number. "You can serve 8 users comfortably. A 9th starts hurting everyone."

Methodology Transparency

Show your work. Every JSON export now includes a methodology block: exact formulas, timing resolution (nanoseconds), token counting method. Reproducible. Verifiable. No black box.

QoL Improvements

  • TUI is the default (just run the binary)
  • Settings persist between runs (no re-setup)
  • Ctrl+C copies (doesn't quit the app)
  • Full run logs for debugging
  • History view with side-by-side comparison
  • Decode loop guard (catches repeating models)
